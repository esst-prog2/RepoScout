## Recommended Approach: B, the short story page

Draft copy below. It's the content for the Impeccable steps: wording can be tightened there, but the facts and numbers stay as written.

### 1. Hero

**Headline:** Is your idea's corner of GitHub alive?

**Sub-line:** RepoScout searches GitHub for a topic, takes the 50 best-matching repositories and shows how many are still being worked on: one sentence, one heartbeat chart, one CSV. No sign-in.

**Buttons:** `Open RepoScout` (to `app/`, the live app) · `View the code on GitHub` (to https://github.com/esst-prog2/RepoScout)

**The contrast pair** (screenshots 1 and 2, side by side; one above the other on phones):

- `mcp server`: **37 of 50 active.** The trace keeps beating.
  Alt text: "RepoScout result for mcp server: Showing the 50 best-matching of 177,486 repos, 37 active among them. Most dots sit in the active zone on the right."
- `angularjs directive`: **0 of 50 active.** The trace flatlines.
  Alt text: "RepoScout result for angularjs directive: 3,137 repos, 0 of the 50 best-matching active. All dots sit in the stale zone on the left."

Small caption: Two real searches, 26 October 2026.

### 2. Who it's for

**Heading:** For people about to build

Before you start a side project, a course project or a new tool, you want to know whether anyone is still working on the idea. Are there active projects you could join or learn from, or is the topic a graveyard of abandoned repositories? RepoScout answers that with one search instead of an afternoon of clicking through GitHub.

### 3. How to read a result

**Heading:** One search, four answers

Screenshots 3 and 4 (`project management software`), with four numbered labels: 1 and 2 on screenshot 3, 3 and 4 on screenshot 4.

1. **The verdict.** One sentence: "Showing the 50 best-matching of 14,067 repos, 10 active among them — most recent entrant pushed 1 minute ago."
2. **The heartbeat strip.** Each dot is a repository. Further right means pushed more recently, bigger means more stars. Three zones: stale (over a year), slowing (3 to 12 months), active (last 3 months). The line along the bottom spikes wherever repositories were pushed, so a dead topic flatlines across the active zone.
3. **The table** (screenshot 4). The same 50 repositories ranked by stars, with last push date, language and activity group. Each name links to the repository on GitHub.
4. **Download CSV.** The same rows as a file (`project-management-software-report.csv`) that you can open in a spreadsheet.

### 4. Try it

**Heading:** Try it

**In your browser:** `Open RepoScout`. Type a topic or click one of the examples. No account, no token. GitHub allows 10 searches a minute without signing in, shared by everyone on the same network: on a busy Wi-Fi, wait a minute and try again (the page says when). Results are kept in your browser for 24 hours, so repeating a search is instant.

**On the command line** (Python 3.10 or newer):

```
git clone https://github.com/esst-prog2/RepoScout
cd RepoScout
python -m venv .venv
.venv\Scriptsctivate        # macOS/Linux: source .venv/bin/activate
pip install .
reposcout search "project management software"
```

It applies the same rules, prints the same verdict sentence and writes the same CSV. With a free GitHub token it gets 30 searches a minute. Link: user manual (https://github.com/esst-prog2/RepoScout/blob/main/docs/USER_MANUAL.md) for other platforms and the token setup.

### 5. What it can't tell you

**Heading:** Honest limits

- **It reads the 50 best matches, not every repository.** When there are more, the verdict says so ("50 best-matching of 14,067").
- **"Active" means pushed in the last 3 months.** GitHub's push time isn't always the latest commit. When we checked 50 repositories, 5 landed in a different group because of that.
- **It matches words, not meaning.** A search can pick up repositories that use the same words for something else. Put quotes around an exact phrase.
- **It's a snapshot.** The numbers on this page are from 26 October 2026. Run the search yourself for today's.

## Distribution Plan

GitHub Pages, source "GitHub Actions" (already set in the repo settings). A small workflow of our own deploys on push to `main`: it assembles the promo page at the root, `site/` under `/app/` and the screenshots, then uploads only that folder. We won't use the suggested Jekyll or "Static HTML" templates: the static one would publish the whole repository. **Cache-busting**, so a browser can't mix an old cached `rules.js` with a new `app.js` (seen on 2026-10-26). GitHub Pages doesn't let us set cache headers, so the URLs themselves change with each deploy:
- **What gets the suffix:** in the app's `index.html`, the links to `style.css`, `vendor/d3.min.js`, `vendor/plot.umd.min.js` and `app.js`. Not the font preload or the `@font-face` URLs: the vendored fonts never change, and suffixing only the preload would download the font twice. Inside `app.js`, the module import `from "./rules.js"`, which a suffix on the `<script>` tag would not cover. The promo page's own CSS link gets one too.
- **The value:** `?v=<short commit SHA>` of the deployed commit.
- **Who adds it:** only the deploy workflow, with a text substitution (`sed`) on the copies in its assembled folder, after copying and before uploading. The files in git keep plain URLs, so localhost (`python -m http.server`) and the tests keep working unchanged, and nothing like a bundler is added. The substitution is checked after it runs: the workflow fails if the assembled `app.js` still contains a plain `from "./rules.js"`, or if any listed `href`/`src` in an assembled `index.html` lacks `?v=`.

### R2-1 — feasibility (minor)

**Problem**

> The plan suffixes the font preload in index.html (`vendor/fonts/archivo-latin-wdth-normal.woff2?v=<sha>`), but site/style.css loads the same font through `@font-face { src: url(vendor/fonts/archivo-latin-wdth-normal.woff2) }` with no suffix, and the sed step only rewrites the listed URLs. The preloaded URL then no longer matches the URL the stylesheet requests, so the browser downloads the font twice and logs a 'preload not used' console warning. The fonts are vendored and pinned, so they don't need cache-busting at all.

**Remedy**

> Either leave the font preload (and the @font-face URLs) unsuffixed, since the vendored fonts never change, or also suffix both @font-face url() values in the assembled style.css so preload and stylesheet request the identical URL.

### R2-2 — completeness (minor)

**Problem**

> The post-substitution check covers only the rules.js import in app.js. A sed pattern that silently misses one of the index.html URLs (e.g. after a whitespace or attribute-order change) or the promo page's CSS link would deploy without a suffix and without failing, which reintroduces the stale-mix risk the section exists to prevent.

**Remedy**

> Extend the check to assert that every listed URL in the assembled index.html files carries `?v=` (e.g. grep for each plain href/src and fail if found).
